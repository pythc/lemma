# 0.8 · 上传、阅读与结果确认

日期：2026-10-17。增量 M8-001；依据用户确认的简化阅读流程，承接 0.7 的批注、问答和工作流。本文不替代已接受 PRD 的十二项职责，也不代表数学核验能力已全部完成。

## 用户流程

1. 首次进入仅展示 PDF 上传入口，论文库作为次要入口。不自动载入教学样本或上次论文。
2. 新 PDF 导入后立即显示阅读器，右侧展示实际评审工作流。默认从第一页、实分析配置启动一次任务；当前自动核查对象仍为选定页中的单条命题，不能称为全篇自动验证。重复导入相同 PDF 恢复已有状态，不自动重发评审。
3. 原文语义需要人工核对时，工作流明确提示，进入既有逐项核对流程；没有自动确认命题。受阻、取消、中断和未执行均按真实状态展示。
4. 评审完成后显示“确定，查看结果”。点击后才展示“评审结论”和“批注”两个标签页。确认只表示打开结果，与数学语义审批分开。
5. 结论页给出选定范围、原文一致性、原证明状态、形式化命题结果和限制；完整依据、复现及覆盖信息作为详情保留。
6. 批注页将每条批注放在对应 PDF 文字旁边。默认只有简述；点击展开标题、详情、原文、协作记录、证据、评论、问 AI 和局部论证。
7. 人工批注在评审期间仍可使用。用户可以选中文字或区域创建批注，评论、问 AI，并显式发起该段的论证。

## 页面与视觉规则

移除常驻左侧功能栏以及顶层“范围与义务”标签。目录、搜索、翻页、缩放和区域批注留在阅读工具栏；覆盖账本收进结论详情“更多核查信息”。评审记录折叠，避免历史信息抢占主流程。

流程以导入、上下文整理、三组职责分支和最终汇总呈现。分支表示任务分类与依赖，不暗示真正并发。任务按钮打开真实产物。深色文字、明确边框、状态文字至少 12px；颜色不能作为唯一状态标识。

桌面 PDF 与页边批注共享滚动区域。批注根据真实锚点纵向排布，发生冲突时依次下移。展开内容限制高度并独立滚动，保持其他批注可见。阅读区域较窄时改为当前页下方卡片；不声称手机尺寸仍有桌面式并排效果。

## 实现机制

- `reading-flow.js`：确认键为 `run.id:run.root`，且必须匹配 PDF 字节摘要、completed 状态和不可变结果根。IndexedDB 按论文存储；换论文、换运行或换根均不继承其他结果的确认。
- `App.jsx`：上传首页、阅读器和右侧工作流；结果显式解锁，来源版本隔离。启动请求使用互斥锁；导航不取消后台任务。返回首页使未完成加载失效。
- `ReviewPanel.jsx`：即使面板打开时任务刚好完成，未确认结果根也只提示回到阅读器，不能绕过结果确认。
- `usePaperReviews.js`：按当前 PDF 轮询，切换瞬间也过滤旧论文结果。失败仅更新提示，不自动重发任务。
- `PdfReader.jsx`：使用 PDF 归一化选区或唯一匹配的原文位置；`ResizeObserver` 读取实际卡片高度以避免重叠。无法唯一匹配的批注明示“本页待定位批注”，不伪造锚点。
- `AnnotationPanel.jsx`：独立卡片及按论文/批注隔离的评论。AI 问答继续使用已有固定原文上下文与归档接口，不将解释当作证明。
- `ReviewSummary.jsx`：三项数学状态分别展示；保留范围、未完成项、证据与覆盖入口。

本次未修改数学合同、证明执行器、模型配置或网关，也未增加自动重试。
