# 0.9 · 自主评审路径与 LangGraph.js

日期：2026-10-17。用户已选定 LangGraph.js，并要求前后端真实执行、路径反映实际任务、每个节点可点开详情。

## 产品行为

首次上传仍直接进入论文阅读器。右侧从实际 PDF 解析开始，展示已经执行、正在执行和明确安排的步骤。协调 Agent 读取全文摘要、带原文锚点的命题和已有核查产物，再决定检查定义、审阅推理、检查引用、尝试形式化或补全领域；不预设所有 Agent 必须参加，也不生成尚未决定的未来节点。

每个节点只展示具体动作、执行者与状态。选择后在路径下方打开一个详情区：为何安排、当前结果、原文位置。完整输入、产物和执行时间默认折叠。原文链接在 PDF 中定位并高亮。新事件到达时保留用户选中的节点。长路径保持可读字号，支持纵横滚动、“回到开头 / 最新步骤”和放大面板，不再把所有步骤挤成缩略图。

“已返回产物”表示执行器返回了内容，不表示数学结论通过。排队分支显示“已安排”，只有真正获得执行槽位的任务才显示“正在执行”。当前网关采用一个模型执行槽位；分支可独立安排，但不伪称同时调用模型。

完成后需要用户点击“确定，查看结果”，才显示“评审结论 / 批注”。批注仍独立显示在原文旁，短描述展开后可查看详细内容、协作与证据、评论和问 AI。形式化命题确认是另一个独立的数学语义关口，不因查看结果而自动完成。

## 技术实现

- Node 后端引入 `@langchain/langgraph@1.5.1`、`@langchain/core@1.2.18` 与 `@langchain/langgraph-checkpoint-sqlite@1.1.0`，锁定到 package-lock。
- `server/adaptive.mjs` 使用 StateGraph、Send、interrupt、Command；SQLite 保存实际执行检查点。框架内部的 read/decide/act/wait/conclude 是能力控制结构，用户界面展示的是每一次执行生成的任务实例及真实依赖。
- `server/adaptive-schema.mjs` 验证模型输出的能力名称、命题 ID、原文锚点、前置产物和重复任务。模型不能注册任意执行器或绕过 Lean 的现有约束。
- 原 `ReviewPipeline` 保留严格的单命题翻译、独立语义复核、人工确认、领域补全、证明修复和真实 Lean 检查。自主评审按需要把它作为子任务调用；子任务不会混入顶层论文历史。
- `src/AdaptiveWorkflow.jsx` 使用 React Flow 与 Dagre 排版。边来自任务依赖；仅在展示层去除可通过其他路径到达的冗余边，完整前置依赖保留在节点详情及证据中。
- 历史任务也按已发生的依赖展示，不再补画固定职责栏。历史记录不能使用新运行时的暂停/恢复 API。

## 数据、审计与恢复

顶层记录包含 `engine=langgraph-v1`、任务实例、命题、核查意见、单调递增 revision、事件日志和最终根产物。每个任务包含唯一 ID、逻辑 key、真实父节点、输入摘要、产物摘要、状态、开始/结束时间；失败重试创建新尝试，保留原失败。

PDF、模型可见输入输出、原文引句、核查意见、子任务结果与报告均写入现有 SHA-256 内容寻址存储。模型响应先归档，再进行引句和结构校验，因此校验拒绝也可以查到模型原始可见响应。这里不保存或展示模型私有思维过程。

SQLite checkpoint 与任务产物缓存共同用于恢复：成功步骤复用，不重复向模型请求；服务停止后的未知外部调用标为中断，由用户显式重试。任务创建前先保存子任务 ID，避免“子任务已经启动但父任务尚未记住 ID”造成重复创建。

SSE `/api/reviews/:id/events` 支持事件序号续接与重放，前端仍保留轮询作为网络错误恢复。连接断开不会重新提交评审。恢复和创建操作保留执行槽位，防止并发请求重复恢复同一检查点。

## 操作入口

- `POST /api/reviews`：`orchestration: "adaptive"` 创建自主论文评审；选区论证仍走原严格单命题路径。
- `POST /api/reviews/:id/pause`：本批真实执行完毕后暂停。
- `POST /api/reviews/:id/resume`：恢复暂停或显式重试受阻步骤。
- `POST /api/reviews/:id/cancel`：终止本轮；不生成完成结论。
- `POST /api/reviews/:id/skip-child`：跳过待确认的形式化子任务，明确保留未解决项。
- 原 `approve`、`retry-translation`、`recover-domain` 继续适用；子任务确认并结束后，主协调器接收真实结果并继续决定下一步。
- `GET /api/reviews/:id/bundle` 导出本轮证据图。全文报告的导出不等于重新运行 Lean；应打开对应命题的核验记录执行原有复现入口。

## 边界与预算

默认最多 24 个专业检查任务、20 轮协调、64 段全文阅读，每段 24000 字符；一次最多安排 3 项任务。每个命题的同类检查最多 3 次。超出预算时保留未解决项并收束；过大的全文在阅读前明确受阻。

本文本层阅读不等于公式 OCR 校对，也不保证模型提取到了每一项义务。检查引用目前只读取提供的论文文本，尚未自动取得外部被引文献。模型认为“本步未发现问题”不是数学证明。只有原单命题链中有固定目标、语义确认及独立 Lean 证据的结果才能标为形式化已证明；整篇论文仍不自动标为正确。

原文锚点只归一化空白与 Unicode 格式，不接受不存在的引句、错误页码或重复而无法唯一定位的片段。不为了完成路径而放宽数学证据要求。
