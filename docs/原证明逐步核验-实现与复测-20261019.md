# 沿原论文证明路线逐步核验

当前验收：两条选定命题均有 Lean 证书；两条作者路线仍未整条通过。代码、真实页面与独立重放已验收，详见末尾最终验收汇总及逐步矩阵。

本次实现针对已批准的原证明验证方案。它与独立证明服务并存：结论独立成立、原证明路线成立、自然语言与形式目标相符是不同判断。

## 实现

- `OriginalProofEngine` 从不可变 PDF 上下文提取实际推导图；步骤包括原文明确写出、省略与引用。每步绑定唯一引句、变量和量词完整的命题及前序依赖。
- 独立语义 Agent 检查目标是否忠实。图是待核验计划，不把未证明节点当作已成立前提；一个分支有疑虑时，其他忠实分支继续执行。
- 每个局部任务是关闭变量后的条件命题。Lean 检查证明或精确否定；成功不掩盖前序义务未成立的情况。反例只针对局部目标，不自动反驳整篇论文。
- 可信 Lean 插桩遍历实际证明项的常量及传递依赖，记录允许公理，并检查所声称前序事实是否实际使用。连接证明可以通过后继步骤传递使用前序事实。
- 依赖审计结合明确的已知定理族和独立 Agent 对实际证明、库签名、原文路线的复核。无法决定所有数学等价关系，语义复核仍属于 AI 判断。
- 编译失败进入诊断、固定库检索、模块补全或辅助引理构造。重试受共享预算约束；不把失败、资源耗尽或模型意见记为数学反驳。
- 全部局部步骤、原文覆盖与连接证明满足条件，才组装整个主目标并再次执行 Lean。未用到的原证明分支、未证明的前序、换路线的独立证明不能升级为原证明通过。
- 服务支持单独发起原证明核验、持久化进度、导出、重放、取消与新版本接续；成功步骤复用。保留失败与中断，不覆盖历史。

## 前端

结果与进度中提供“原证明核验”。每个步骤可以展开：当前判断、采用的前序事实、原文位置、精确 Lean 目标及证据。原文旁生成独立的可折叠批注。保留现有的连续阅读、PDF 原生目录和最终结果确认；不增加执行统计或全部调度日志。

## 结果用语

- 沿原文通过：局部 Lean 检查及独立路线评估通过，前序义务已成立。
- 补全后通过：补出原文省略的推导后通过；补全内容单独记录。
- 局部命题有反例：精确局部目标的否定通过 Lean。
- 本次形式化路线冲突：生成证明使用了被限制的依赖或改变路线。这不等于作者的数学命题已被反驳。
- 仅条件推导通过：依赖前序尚未成立，不能组成完整证明。
- 仅替代证明通过：可作为独立数学证据，不能替代作者路线。
- 暂未核验：翻译歧义、覆盖缺失、工具失败或当前搜索没有完成。

## 自审后补充的验收约束

1. 候选自己声称“原路线／独立证明”不决定结论；所有内核接受的证明候选均交独立路线评估。判断依据包括原文、固定目标、实际证明、库声明和方法限制。
2. 局部目标本身可包含前序推理的具体前提，因此不强制每个局部证明重复调用所有全局辅助定理。记录实际 binder 使用；整条连接只能沿实际使用关系追溯，不能拿规划图中的虚构依赖补足覆盖。
3. 传递依赖采集是对 elaborated expression 的语法依赖审计，不是最小依赖证明。无效的辅助命题提及仍需要独立路线复核；当前系统不能机器判定任意数学等价关系或全部语义忠实性。
4. 路线评估缓存绑定原文、目标、证明、依赖和方法限制的指纹；连接评估另绑定全部局部结果。变更后不得复用旧的肯定意见。重放检查对应证据、来源链及连接评估的范围。
5. 辅助引理构造只生成新候选，不修改原证明图；诊断翻译遗漏后，在新图版本中修正目标并保留旧版失败记录。独立分支继续执行。
6. `verificationOnly:true` 固定候选重查仅消费已保存候选：不提取新图、不生成新证明、不重新发出旧的未知请求；重新执行 Lean，必要时重新判断路线。没有收到候选的步骤继续未核验。

## 原 PDF 对照记录

- BW 第4页确实印有“B(y0, ε*) 有限，因为 ε 是上确界”。这不是 OCR 把另一半径识别错了。需要明确上确界逼近、带的覆盖和边界情形；不能仅凭本轮未能生成 Lean 证明就称其为数学错误。
- BW 的局部引理只为 y∈[0,1] 写出，后文却在 y0±ε 调用。需要补充中心在区间外时的处理。把 y0±ε∈[0,1] 直接加成形式目标中的新假设，不是原文忠实翻译。
- Yang–Zhu 第3页在望远镜求和前明确写了“Since f is monotone”。漏掉这一假设属于我们的目标提取问题，不属于论文遗漏。
- Yang–Zhu 的压缩点仍在 I 内、σ 之间共用单调方向、另一单调／凹凸情形及有限区间排序，需要显式形式化。它们未被本轮工具证明，不等于已被反驳。

原 PDF 图像与逐页提取身份记录在 `evidence/original-proof-20261019/visual-source-review.json`。这些人工视觉核对用于归因，不替代 Lean 证书或自动修改已保存结论。

## 候选保留、目标纠错与进度一致性

- 历史成功和失败的证明文本进入带原文锚点、原目标哈希和不可变来源的候选库。目标修订后可以复用文本，但不得继承原检查结论，必须在新目标下重新运行 Lean 和路线复核；旧失败文本也可能在纠正翻译后变得可用。
- 以前一版本的翻译诊断作为带来源的可疑观察，交独立语义 Agent 对照 PDF，而不是偷偷加成新前提。第二篇中把 `f(b)` 写成 `b`、曾漏掉原文单调性，属于框架提取问题。
- 同一评审的并行进度写入按路径排队，避免旧的大快照覆盖新的完成结果；不同评审独立保存。证据内容哈希算法不变。
- 最终源码的 226 项离线测试、11 项原证明/自动流水线实际 Lean 和 HTTP 集成、此前 8 项基础 Lean/历史重放（合计 19 项不同工具测试）、4 项 Sites 检查和构建通过。写入修复后另重跑原证明 HTTP 接续验收通过。记录中的更早数字属于历史快照。
- 真实论文先保留原始运行，再由最新引擎自主修复，最后对已收到候选做固定候选重查和独立 Lean 重放。目标版本不同的历史通过步骤不合并成一个虚假的完整证明。

- 原图修订后的重放仍按诊断实际所属的旧图检查目标与来源，不要求旧诊断伪装成新图记录；新增了语义响应不完整、重提图后仍能独立重放的回归。

- 辅助引理审核尚未通过时，后续修复只接收编译诊断，不把完整常量依赖图再次塞入请求；原依赖图仍独立存证。最新 7 项原证明实际 Lean/HTTP 回归已完整重跑通过。

- 用户可见的证据摘要同样过滤运行上限中的调用和输入计数；原归档不变。新增界面泄漏回归后，226 项离线测试通过；最终构建与 4 项 Sites 检查通过。


## 源文一致性与大包导出增量

首轮独立语义意见曾同时承认“目标忠实”并因“该命题很强/可能不可证”而阻断 Lean。现将数学疑点单独归档，只以具体公式、量词、定义域和前提不匹配触发翻译修订；原文可能错误的命题仍可进入精确反例核验。记录 `sourceAlignmentPolicyVersion:2`，旧策略缓存需重查。这是针对实际首轮误分类的修正，不由框架直接代替数学判断。

首轮两项评审均已保存结束状态，但旧导出脚本在整体 JSON.stringify 时超过 V8 单字符串上限。没有重发模型请求来修复导出。新 NDJSON 导出和逐条读取已保住 BW 503 个、Yang–Zhu 170 个原始产物，完整哈希和依赖校验通过；主入口、原证明与命题下载支持新格式，旧 JSON 仍兼容。总量上限 2 GiB、单记录 200 MiB，重放仍需与证据规模相称的内存。

BW 首轮的大包还在当前规则下重新执行了 5 个 Lean 检查，内核均通过；其中 3 个的旧审计字段与新策略不同，因此整个旧结果的 reproduced 为 false。不能将其写成完整历史重放通过，更不能将它当成 5 个原文步骤全部成立。最终成绩以后续新策略固定候选重查与重放为准。

流式导出/读回、共享依赖、篡改、截断、HTTP 回压和失败保留旧文件回归通过。当前 229 项离线测试、19 项不同真实工具/Lean/HTTP 控制验收；新流式 HTTP 下载已在原证明实际 Lean 接续测试中验证。真实论文后续结果仍在执行，单独追加。

## 省略推导的目标恢复

实际 BW 接续中，模型把“WLOG 可缩放到 [0,1]”记录成省略步骤，却把待核验目标留空；旧版曾有可重新编译的归一化证明。这是框架形式化覆盖的问题，不能记为论文错误。

现对明确步骤和省略步骤增加一次目标恢复：输入固定原文、已有图及同一原文位置的历史目标提示，只允许填写 null 目标，不能改已有命题、位置、依赖或方法限制。恢复后重新独立复核原文含义，再交 Lean。引用陈述未取得时保持未核验。仍无法表达的目标记录失败；其他分支继续。历史提示可能带前序绑定，恢复时必须区分原始局部命题与包装后的条件命题。

本轮追加的 `goalRecoveryOnly:true` 接续只补缺失目标、复查已收到的局部候选，必要时补连接证明，不启动新一轮局部证明搜索或递归改图。它与完全固定图的 `verificationOnly:true` 分开记录。正常评审不需要用户选择这些模式。局部证明重查、独立语义判断、旧图身份不变与恶意改写拒绝已纳入控制验收；232 项离线测试通过。

用户要求先不处理知识库故障，本轮不再连接或重试知识库；文档与源码、设计资源、论文和证据先归档本机。历史知识库页面不作为本轮交付完成的依据。

## 逐步调度自审修正

源证明图的首版调度仍按 ready 批次等待，可能让短分支的后继等待另一个长分支。现改为逐个完成唤醒：后继只等待它自己的前序节点，实际并发仍受模型和 Lean 资源池控制。局部失败记录为未验证，后继只能得到条件推导；持久化异常等待在途工作结算后退出，不自动重复请求。控制测试用一个必须等后继启动才结束的慢分支确认已不存在批次屏障，并检查错误不被重复调度。

自审还加强了局部接受条件中的证明／否定方向一致性检查，不能因检查器返回其他方向的成功就记为反例。234 项离线测试通过。当前正在执行的双论文自主接续已载入先前版本，未为更新代码中断请求；后续目标恢复与固定候选审计采用新版本，源码身份分别保存。

另一次源文检查发现，当前 BW 的更大带目标把 ε* 量化成任意正数，却没有保留原段落中“两个端点有限邻域半径的最小值”的关系及条件。该版本目标可能脱离源文上下文，不能据其反例归罪于作者。观察绑定旧图与精确目标，保存在 `source-context-inspection.json`。语义策略更新为 `sourceAlignmentPolicyVersion:3`，强制独立复核上下文中参数定义、丢失前提以及新增前提；旧版缓存不作为新版复核。文件名 `policy2` 是本次驱动的历史阶段名；最终报告采用 `proofPolicyVersion:3` 与 `sourceAlignmentPolicyVersion:3`，以报告字段及源码摘要为准。

旧 BW 归一化候选使用完整句子作锚点，新图只截取同一句中的 WLOG 从句；仅按引句字符串相等会漏掉候选。现额外接受同页、相同 sourceTextHash、已验证字符区间包含且至少 40 字符的锚点匹配，候选仍在新目标下编译。不同源文哈希或不重合位置不匹配。两份真实图的只读核对记录在 `source-match-check.json`；这只是候选定位通过，不是证明通过。

## 方法限制精度的实际边界

当前 BW 图提取了 `forbiddenFamilies:monotone`，比原文“不采用单调子列定理”的声明更宽，会同时命中有序运算的普通库常量。这些名字命中本身不能证明作者路线被替换。观察保存于 `source-policy-inspection.json`；本轮“路线冲突”必须解释成当前形式化在该版本限制下未通过，不能解释成作者数学错误。限制与命中结果按图版本保留，可在证据中对照适用范围。另一个独立事实是实际证明记录了 Classical.choice 依赖；它不能证成“不使用选择公理”的声明，也不能证明原论文在数学上必须使用选择公理。当前依赖审计不是最小公理或所有数学等价关系的判定器。

## 命题证书与作者路线分开闭合

Yang–Zhu 自主接续完成了 8 个局部证明，独立 Lean 重放全部复现；但连接评估发现方向桥重新证明了单调性核心，前面的 Lemma 1 未被实际沿用，因此原路线仍为 partial。这不是定理被反驳。

现补充独立闭合：只消费已收到且核验过的局部证明与条件连接，把它们组合成精确根命题，再实际运行 Lean。允许公理、原文身份、定义与引理环境必须与根合同一致。该证书单列 `independentTheorem`，不能升级原路线分类；接续和独立重放再次检查封闭证明。源文含义存疑仍可使作者路线未验证，但不会抹掉对固定数学命题已经成立的工具证据。正常流水线只在目标哈希完全一致时复查并复用，避免重复模型证明请求。

对 Yang–Zhu 已实际取得封闭主命题证书，目标哈希保持 `6654ad46f8716c8503700efa4aeed9aeee84b787641843b9f35b69634b880f35`；探测产物为 `73a086dbc0b72ef35f7fdb3afb0f519e1b134742fff4c855a64b6f4992dabbc8`。这条记录证明选定形式命题，不代表作者全部证明路线或全文认证。后续最终审计仍将重新检查。

本增量 236 项离线测试、7 项原证明实际 Lean/HTTP 验收通过，包含路线拒绝后保留独立命题证书、HTTP 分类与重放。证书复用最初使用了与旧协议重放不同的插桩选项，两次检查均通过但 sourceSha256 不同，因此 reproduced 为 false；统一 R10 参数后，4 项完整上传→LangGraph→语义决策→原证明→证书复用→父结论→重放集成全部通过。初次失败日志保留，未把 revalidated 冒充 reproduced。
