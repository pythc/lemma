# 自主原证明构造与干净复测

新评审从论文 PDF 和核查重点开始，由产品内的 Agent 选择环境、表达目标、拆分原证明、构造引理并处理编译失败。开发者针对某篇论文补写的证明不进入新会话的候选，也不作为自主能力的验收证据。数学核验是否通过，以本次确切目标的 Lean 产物为准。

## 证明构造与修复

原证明 Agent 先生成带原文锚点的依赖图，独立 Agent 检查命题、条件、量词与原文是否对应。Lean 在局部求解前检查各引理接口的类型以及假定所有局部结论时能否连接根目标。编译失败触发接口修复和再次来源复核；类型检查成功不代表引理已证明。

证明图提取、接口设计及接口修复也由 Deep Agents 的规划模式执行，可以查实际声明、搜索数学库、调用条件引理计划检查。规划模式不开放证明记忆、安装及环境变更工具，也不把图中的条件连接证明记作根目标证书。证明构造在后续独立阶段执行。六类语义对照若采用完整的对象格式，只做无损转为数组并记录转换；缺项、错误片段和无效来源仍拒绝，不能通过格式修复补出数学内容。

目标翻译本身也能迭代。仅来源位置错误时保留数学目标，只修对照证据；目标的语法、类型或含义需要修正时，Agent 根据实际诊断对同一选区重新翻译，建立新版本。新版本保留固定的定义和环境，但清除旧审批、证明、路线与通过状态，重新进行 Lean 类型检查及独立语义复核。旧目标即使已被 Agent 接受，也只保留为历史，不会被就地改写。语法检查、类型检查与内核证明的输出分别传递，不因精简日志丢失错误位置。

Deep Agents 工作器可以使用以下工具自主构造更小的数学义务。

| 工具 | 作用 | 验收边界 |
| --- | --- | --- |
| plan_lemmas | 声明引理依赖及父目标的连接证明，先检查接口 | 引理仍待证明 |
| check_lemma | 编译单条引理的完整条件证明，保存诊断 | 只核验此条件命题 |
| assemble_lemmas | 使用全部已证明引理生成自包含父证明并重新编译 | 缺少任何引理就不能组装成功 |
| proof_projects | 返回本次构造的引理、状态与缺口 | 不以进度代替证书 |

难引理可以继续拆分为子项目，最多使用共享策略允许的深度和规模。子项目关闭后仍须重新核验父引理。失败证明保留，完全相同的重复候选返回原诊断；新的构造可以再次检查。不同环境的项目不能相互冒用结果。

辅助引理的候选及失败经验也进入同一会话的证明记忆，工作器可按已声明的精确引理目标检索。修改连接方案后，成功的同文证明重新检查并登记到新计划，避免“返回旧成功收据但新计划仍缺引理”的状态错误。已安装外部库可以绑定到根计划，其依赖成为新环境合同的一部分。

这些工具与现有的数学库检索、兼容安装、环境切换、候选分支、工具调用和证据保存共用运行限制。工具内部的失败恢复不改变根目标，也不允许添加未证明公理。后续原路线审查仍检查实际依赖，防止使用根定理或等价结论绕过作者论证。

## 新会话的证明来源隔离

新模型评审创建独立的证明会话。原证明服务拒绝该会话的外部证明图和定理候选，并拒绝继承其他会话的证明检查点。证明记忆仅返回同一会话产生的候选。当前会话中的失败和成功可供后续修复使用，使用时仍重新检查。

显式的高级输入与历史回放保留各自来源，不能被标成从原文开始的自主评审。来源对齐、原证明有效性、独立证明的真实性和构造过程是否自主，分别记录。

领域补全和翻译修复保留同一证明会话。首次翻译未形成目标时，补全方案仍须保持选定原文引句；改选同页其他定理会被拒绝并进入方案修复。同一命题已有形式化恢复分支时，不再自动派发竞争的翻译或补库分支；不同命题及独立的原文检查仍可并行。

## 复测输入与判定

通用入口为 math-review-bot/scripts/evaluate-autonomous-paper.mjs，输入仅有 PDF 路径、空输出目录和自然语言核查范围。运行前保存论文摘要、范围、实现文件摘要和历史导入数量。运行后保存子任务、证明图、局部结果、组装、回放以及实现文件变化记录。

| 样本 | 输入版本 | 核查重点 |
| --- | --- | --- |
| Yang–Zhu，From Uniform Continuity to Absolute Continuity | arXiv 1011.6471v2 | Lemma 2 及其依赖的 Lemma 1 |
| Sidi，Analogue of the Cauchy–Schwarz Inequality for Determinants A Simple Proof | arXiv 2403.19691v1 | Theorem 2 及其依赖，保留不等式和等号条件的区别 |

两篇论文各使用新的空证据目录，不导入旧 Lean 目标、证明图、开发者候选或历史定理证书。样本固定后不根据通过情况更换论文。对新论文的部分特例通过，不能代替原目标通过；两篇样本也不能给出通用成功率。

分别报告原文定位、目标翻译、证明拆分、辅助引理构造、局部 Lean 检查、完整组装、原路线审查和独立回放。遇到未明确返回的外部模型请求，保留未知状态，不自动重发。开发阶段的脚本化模型测试只用于验证工具机制，真实论文能力以产品中的真实模型调用为准。

## 实施与结果记录

实现位于 server/lemma-projects.mjs、server/proof-autonomy.mjs，并接入现有 Deep Agents、原证明服务及全文评审流程。常规及原生验证记录、真实论文复测结果统一归档到 math-review-bot/evidence/autonomous-source-20261020。

最终测量结果以该目录中的每篇 result.json 和后续增量历史为准。远端知识库同步继续暂缓。

## v6 通用执行与接续修复

工具调用历史达到工作上下文阈值时，通过同一模型传输、预算和取消链生成公共导航摘要。原始任务和当前环境目标保存在工作区；原始模型及工具收据保留在内容寻址证据中。实际序列化请求另有预发送软阈值，以覆盖普通 token 估计漏掉的私有上下文尺寸。仅本地预发送拒绝可以触发压缩重试，未知网络结果不因此重发。摘要既不证明引理，也无权更改命题。

诊断命令使用当前环境中通过身份校验的编译库路径，保持离线沙箱和目录隔离。切换环境后同时更新目标文件、当前合同和后续证书，不把旧环境检查结果冒用到新环境。尚未移植的自定义定义或外部闭包仍明确不可用，不承诺任意 Lean 版本都能自动迁移。

成功和失败任务都把实际 harness 收据根接入导出图。旧版遗漏的边不改写历史根；通用检查点分叉可按所属评审、源文、目标、会话及阶段时间范围收集已经收到的工作器收据，建立新的来源产物。检查点表示收到的阶段结果，并非整篇评审已完成。

接续入口仅接收旧记录身份、全新输出目录及可选的原生重查模式，不接收手工数学编辑。它在启动服务恢复前拒绝仍有运行记录的存储，避免修改另一个进程的任务。正常接续沿用原会话及原证明图，保留失败和未知结果；固定候选重查不发模型请求。跨实现版本、额外预算段与首次运行结果分开记录，不把接续包装成新的独立测试。

## v7 本地库源码与阶段适配

实际评测发现，原源码工具只接受经远程检查的外部仓库，Agent 读取已经安装的 Mathlib 时反复卡在检查前置条件及网络错误。新增本地固定 Git 对象读取，`read_library_source` 默认选择 pinned Mathlib；支持有界行窗口与后续行游标，同时记录完整源码和窗口摘要。源码只用于查阅，不构成导入可用性或数学证明。外部库读取仍固定提交、限制下载字节，并拒绝无效编码。不同封装环境不会冒用默认 Mathlib 身份。

同一证明引擎有全文评审和独立证明服务两个阶段适配器，分别产生 task:R06_INTERFACES 和 original:R06_INTERFACES 等收据。接续现在严格接受这两套既有类型，而不是任意放宽类型；图、目标、源文和会话摘要仍核对。新增失败回归复现真实旧检查点问题，修复不修改历史目标、证明图或数学证明。

## v8 工作区与即时导入

真实命令记录显示，SDK 虚拟绝对路径与 shell 的真实当前路径混用会使探针写入错误目录。工作区适配器将其自身的真实路径映射到相同虚拟文件，同时保留越界及符号链接保护；不提供宿主项目、历史证明或密钥目录的访问。固定任务／目标及 Goal 编译文件只由框架维护，普通命令与 SDK 文件操作不能改写。

新增 prepare_goal，按当前已核验环境编译固定命题的签名，供探针 import Goal；它不会证明该命题。以 False 为目标的签名也能编译，但最终证书必须为空。切换环境、增加导入后清除旧 Goal 编译对象，并保持签名目标与当前合同一致。探针可导入 Goal，最终证明仍必须在当前合同内自包含，不能引用临时模块。

新增 add_mathlib_modules，读取固定 Git 提交的模块清单、准备编译缓存并生成新环境合同。保持目标原文、量词表达、假设元数据、源文、既有模块身份、定义及已证引理；不允许移植到未支持的封装环境。源码查阅、导入就绪、签名编译、局部证明和完整组装分别记录。结构不变检查不等同于内核证明自然语言等价，正式局部及根证明仍重新检查并进行独立路线评估。原生命令和 Goal 准备与其他 Lean 检查共用资源及库读写锁。

## v9 评审约束的独立校正

方法限制与 Lean 语法规则分开处理。评审器把 axiom、sorry 等命令误放入声明名称片段时，系统让独立 Agent 对照原文和方法声明判断：这是已由固定内核准则执行的语法禁令，还是作者明确避免的数学方法。只允许校正这些模糊命令项；既有精确声明、公理和其他方法片段不能删除。转换成新方法限制必须给出精确 Lean 名称及真实原文锚点。没有明确结论时仍执行原限制，整条原证明不记为通过。

决定保存于单独收据中，不修改原始证明图、数学目标、定义、证明内容或旧限制。新策略报告版本为 4；旧报告按原版本重放，新报告重放时重新检查决定的范围、证据及全部保留规则，随后重新运行 Lean 和依赖审计。该过程是可追溯的 Agent 语义判断，不能当作内核证明自然语言含义。

正常接续默认不重发未知外部请求。策略审查请求超时或进程在发送后中断时，接续会保留未知结果；即使另一轮评审意见改变了原策略，也不因此自动重发。已知格式错误最多两次修复，受同一调用及输入预算限制；只重查收到的候选时不请求策略模型。旧约束无法自动确定则保留未核验状态。

## v10 中间候选恢复与完整收据闭包

工具中间检查成功、最终回答格式失败是两个不同结果。工作器已经通过 Lean 检查的候选，不应因为之后的回答格式、路线字段或预算失败而消失。所有原证明阶段及局部失败的收据都进入完整报告的依赖闭包，中断报告也保存已经收到的收据。新报告的回放检查这些执行收据是否确实可达。

接续从不可变报告、同一原文与精确根目标、同一 Agent 会话识别历史工作器；校验工作器收据与所属评审，不根据论文名称选择候选。只恢复已经收到的原生候选文字，不导入其他会话、不同定义或目标版本，不重发未知请求。旧版漏链的工作器另建恢复来源记录，不修改旧证据根。每个候选仍须重新编译并取得新的作者路线判断；旧策略下的接受或拒绝状态都不会自动继承。

引理命名约束同步到工具 schema，并区分命名与用途错误，减少格式试错。评测接续可显式指定本段模型调用数，必须在共享上限以内，随输入归档。产品默认仍为 256 次；最终候选恢复复查使用 64 次追加调用段，单独报告，不算一次新的空库测试。

## v11 候选与导入环境共同恢复

正常接续在选择候选后，再恢复候选所需的合同与导入清单。此前先绑定基础环境、后选择候选的顺序会丢掉它在构造时补入的模块。恢复依然检查精确原文、目标、前提、定义和元数据不变；并不允许用旧合同替换新数学目标。候选原生通过的历史标签还必须满足退出码和允许公理等完整条件，不能仅看 status 字段。

原生回归使用一个编译时确实需要额外模块的候选：同一测试在修复前不能闭合，在修复后通过局部核验、完整组装及独立回放。真实论文再做一次明确的 32 次调用接续段，保留前一段 64 次结果与所有失败；该短段用于核对恢复路径，不能被当成新的空库测试或全局运行上限。
