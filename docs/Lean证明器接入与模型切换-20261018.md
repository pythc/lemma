# Lean 证明器接入与模型切换 · 2026-10-18

状态：核心接入及兼容性已验证，真实论文对照仍在进行。本文是增量技术记录，不将批准方案的全部研究与评测目标标为已完成。

## 当前实现

保留 LangGraph.js、全文阅读器、原文批注、合同与语义确认。单命题证明阶段接入独立的交互搜索适配器：当前环境检索 → LeanCopilot/Aesop → 完整候选生成或局部策略修复 → 干净 Lean 检查器。容易目标可以完全不调用模型。所有路径都固定目标、导入、领域定义和允许公理。

搜索会话持有同一目标的所有耦合子目标。失败策略回退；成功前缀存为可重放策略日志；新进程重新执行日志，而非复用失效的状态 ID。检查点匹配目标与环境身份，模型不能修改目标来消除错误。完整证明模型调用期间关闭空闲 REPL；实际活跃会话受单独资源池约束。

搜索态允许 LeanInteract 必需的内部占位，但它不是证据。检索排除该占位命题；禁止循环自引用、`sorry`、新公理及命令注入。Copilot 的搜索命令须提取为普通证明脚本，然后交给现有只读、禁网、干净目录中的 Lean 检查器；搜索返回完成不直接写 verified。最终检查继续核对精确目标、编译退出结果和传递公理。

本次实现只提升独立证明或精确否定证明的构造机制。`originalProofVerification` 仍为 `not_implemented`，独立重证不能证明论文作者的每一步都有效。用户确认自然语言与 Lean 目标之前，产品不会自动执行论文级批准；隔离固定目标实验不写入语义批准，也不生成论文通过结论。

## 模型切换

Pro 的直接错误已定位为上游 `usage_limit`。用户确认使用个人空间，随后要求改用 DeepSeek 官方接口。仅凭现有诊断不能给出 Pro 的具体剩余额度或重置时间。

本机现用：`https://api.deepseek.com/v1`、`deepseek-flash`、`reasoning_effort=high`、单进程模型并发 1。依据 [DeepSeek 官方说明](https://api-docs.deepseek.com/quick_start/agent_integrations/)，该 API 名称对应 V4.1 Flash 系列当前版本。真实连接请求返回 HTTP 200、`finish_reason=stop`、正确 JSON 结果；应用 `/api/status` 也确认新配置。

密钥只保存于 Git 忽略的 `.env.local`，权限 0600；不写入本文、知识库、模型输入或评测报告。Goedel 是单独的可选本地证明生成器，不替代用户选择的论文阅读模型。

普通证明默认最多 10 分钟、8 个候选、4 次模型请求、64 次策略调用，每次最多 32768 输出 tokens，总预留 131072 tokens。专用模型每次另限 120 秒；任一总预算先到则停止。当前先尝试用户配置的模型及其编译反馈修复，再将本地专用模型作为候选备选；本地短预算实测尚未显示两篇论文目标的收益。

已完成响应明确返回 `length`，记录为输出预算不足，不当作数学错误，也不误记为外部结果未知。超时、传输丢失或缺少终态证据时不自动重发。内存保护包含进程组清理、MLX 内存配置及 REPL RSS 采样；RSS 采样不是操作系统分配级硬上限。
