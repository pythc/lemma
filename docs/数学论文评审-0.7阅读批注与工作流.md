# Lemma 0.7 · 阅读批注、上下文问答与评审工作流

日期：2026-10-17。决策来源：用户确认以 Zotero 的阅读结构为基础，结合 Semantic Reader 的页内标记；多 Agent 协作与证据在选中批注后展开。本轮已实现本机产品，不只是设计稿。

## 产品体验

阅读视图以原论文为中心。左侧保留目录、搜索和导航，右侧是页边批注。默认每条批注只显示两行以内的简述、来源和页码；点击后展开标题、内容、原文、协作任务、证据、评论。评审记录按 PDF 版本与原文位置关联；同一位置默认展示最近一次评审，旧记录仍在历史中。

选中文字后，可添加批注、问 AI，或发起局部论证。人工批注支持评论，人工复核只记录人的判断，不改变机器结论。框选没有可提取文字时仍可写笔记，但不能直接发送问答或论证，页面会说明需选择原文文字。

问 AI 打开小窗口，固定当前原文选区，可解释概念、追问与判断是否值得进一步论证。窗口支持最小化、关闭、停止回答、来源回跳、回答依据和新对话。点击论证进入工作流设置，由用户启动任务；解释和建议本身不执行证明。

新 PDF 成功导入后进入工作流准备页，选择页码和数学方向，再开始评审。流程从“论文已导入”进入“理解原文与上下文”，按原文与语义、原证明审阅、构造与机器核验三组职责展开，最后汇总。节点绑定真实任务；等待确认、受阻、中断和完成均单独展示，失败不会汇总成通过。点击节点可看真实依赖与产物。

## 技术方案

保留 PDF.js 的真实画布和文本层。原文定位仍绑定 PDF SHA-256、页码、引用文本及归一化坐标；自动评审批注根据原文在文本层定位，不编造页内位置。导入、旧批注、范围义务账本及完整评审入口继续可用。

新增 ReaderAssistant 本机服务。POST /api/reader/chats 创建异步问答；GET /api/reader/chats/:id 查询；POST /api/reader/chats/:id/cancel 取消。服务端重新解析 PDF，检查文件身份、页码及选区唯一性，再调用现有 OpenAI 兼容适配器。与评审共用执行占用保护，不自动重复生成。

模型只返回解释、原文引用和论证建议。引用须能在实际上下文中定位。无效引用导致回答受阻，原始响应仍归档。reader_source → reader_model_response → reader_explanation 通过内容摘要关联；历史回答只能来自同一文件、页码与选区的已完成服务端记录。模型输出保持“解释，非核验结论”。服务重启把进行中的回答记为中断，不自动重发。

人工批注、评论和对话索引保存在浏览器 IndexedDB；问答任务、原始模型响应和证据保存在本机 API 的运行存储。评论通过事务追加，避免并发覆盖。已有批注导出包含评论，但不是额外核验或完整证据包。

局部论证向现有 ReviewPipeline 传入 focusQuote。在模型执行前检查原文锚点，模型提取后再次检查选区文本未变化；不一致时在创建目标及机器核验前阻断。原有语义确认、目标版本、领域补全、Lean 与证据重放约束保留。

工作流按真实任务状态轮询，并从任务 inputs/output 得到依赖。树形分组用于阅读进度，不表示所有 Agent 同时运行。没有伪造进度百分比，也没有用演示输出替代实际任务。

## 验证与明确边界

自动回归 73/73 通过；Sites 包装检查 4/4 通过；生产构建通过。首次回归发现导出声明不含既有测试要求的“未执行”文字，补回明确范围说明后通过，原失败日志保留。构建仍提示主 JS 约 870 kB，尚未做分包优化。

浏览器使用 Edge；应用内浏览器连接超时后采用可用浏览器验收，没有更改扩展安全权限。检查了新文件导入、选文批注、评论、历史恢复、两轮问答、引用回跳、局部论证、受阻任务、证据、历史汇总及窄屏。两个验收页控制台未观察到 error/warn。

问答测试使用单独端口和运行目录的明确标注受控模型，不读取本机模型配置、不调用真实模型。历史已证明样本用于检查呈现，不是本轮重新证明的真实论文。真实 Thinking/high 网关仍在联合定位无最终答案问题，不能据此宣称本轮问答质量或真实研究论文端到端通过。

当前自动评审范围仍是选定页或选区中的一条命题。工作流不是全篇自动核验，原证明审阅也不等于原证明逐步机器核验。全篇结论与依赖完整性仍需“范围与义务”账本。扫描件 OCR、跨设备同步、复杂双栏/公式选区的全面验证均未完成。
